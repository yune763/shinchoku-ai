# 進捗管理AI — 社内チーム接続ガイド

> **現在の公開URL（社内に共有するもの）**
> ```
> https://created-fort-sleep-dynamic.trycloudflare.com
> ```
> ※ ホストが `cloudflared` を再起動するとURLが変わります。変わったら新URLで再接続してください。

各自のPCの **Claude Code / Cursor** を、中央の「進捗管理AI」へ接続し、
作業ログ（現在地の把握・ステップ完了・コメント・コミット）を中央の進捗表へ流し込みます。

構成:

```
[ホストPC(1台)] npm run dev(:3000) + Cloudflare Tunnel ──→ 公開URL(https://xxxx.trycloudflare.com)
                                                               ▲ MCP / REST
[各メンバーPC] Claude Code / Cursor ──(MCP: 公開URL)──────────┘
```

---

## A. ホスト側（中央サーバーを出す人・1台だけ）

1. アプリ起動: `npm run dev` （→ http://localhost:3000）
2. トンネル起動（別ウィンドウで常駐させる）:
   ```
   cloudflared tunnel --url http://localhost:3000
   ```
   表示される `https://xxxx.trycloudflare.com` が **公開URL**。これを社内に共有する。
3. 注意:
   - このURLは **トンネルを起動し直すたびに変わる**（無料のクイックトンネルのため）。
     URLを固定したい場合は Cloudflare アカウント＋独自ドメインで「名前付きトンネル」にする。
   - ホストPCの `npm run dev` と `cloudflared` を **起動したままにする**（閉じると全員つながらない）。

> 認証トークンを有効化する場合（公開URLを閉じたい場合）:
> `.env` に `API_TOKEN=<長いランダム値>` を設定して `npm run dev` を再起動。
> 各メンバーは接続時に同じトークンを `SHINCHOKU_TOKEN` として渡す（下記 B-3 参照）。

---

## B. メンバー側（各自のPC）

### 前提
- **Node.js** が入っていること（`node -v` で確認）。無ければ https://nodejs.org からLTSを入れる。
- **Claude Code** または **Cursor** が入っていること。

### 1. このプログラムを入れる
ホストから配布された **このリポジトリ一式**（zip か git clone）を任意の場所に置き、依存を入れる:
```
cd 進捗管理AI
npm install
```
> メンバーは `npm run dev` を **起動しなくてよい**（中央につなぐだけ）。必要なのは `mcp/server.mjs` と依存のみ。

### 2. 中央URLへ接続（ワンコマンド）
ホストから受け取った公開URLを指定して実行:
```
node scripts/connect.mjs https://xxxx.trycloudflare.com "あなたの名前"
```
これで Claude Code に `shinchoku` MCP が登録されます（中央URLに向く）。
Claude Code / Cursor を **再起動**してください。

### 3.（認証トークンがある場合のみ）
ホストが `API_TOKEN` を有効にしている場合は、MCPにトークンも渡します:
```
claude mcp remove shinchoku
claude mcp add shinchoku --env SHINCHOKU_BASE_URL=https://xxxx.trycloudflare.com --env SHINCHOKU_TOKEN=<トークン> -- node "<このリポジトリ>/mcp/server.mjs"
```

### 4. 動作確認
新しいセッションで:
```
/progress
```
中央の「次に着手すべきゴール」が表示されれば接続成功です。

## C. 作業ログの流れ方

メンバーの Claude Code は、中央の進捗表へ次のように記録します（CLAUDE.md のルールに従い自動で行います）:

| 操作 | 中央への反映 |
|---|---|
| `set_active_goal` | 作業中ゴールを設定（以後の記録先） |
| `add_log` | 結果・コメント・成果物を記録 |
| `set_step_done` | ステップ完了（進捗%が自動再計算） |
| `update_goal` | 現状・状態を更新 |

### （任意）コミットも自動で中央に流す
自分の開発リポジトリで、コミットのたびに中央へ記録したい場合:
```
# そのリポジトリで、環境変数に中央URLを設定した上で post-commit フックを入れる
set SHINCHOKU_URL=https://xxxx.trycloudflare.com   (Windowsの例: PowerShellなら $env:SHINCHOKU_URL=...)
node "<このリポジトリ>/scripts/report-commit.mjs"   # 単発テスト送信
```
> 常用する場合は各リポジトリの `.git/hooks/post-commit` に `report-commit.mjs` を呼ぶ1行を足し、
> `SHINCHOKU_URL` を公開URLに設定してください。あらかじめ中央で「作業中ゴール」を設定しておくと、
> コミットが自動でそのゴールに記録されます。

## よくある質問

- **URLが変わった**: ホストが `cloudflared` を再起動すると変わります。新URLで B-2 をやり直してください（固定したい場合は名前付きトンネル）。
- **つながらない**: ホストの `npm run dev` と `cloudflared` が起動中か、公開URLが正しいかを確認。`node scripts/connect.mjs <URL>` は到達性チェックも行います。
- **ブラウザでも中央を見たい**: 公開URLをそのままブラウザで開けば、中央の進捗画面が見られます。
